📖 Regex Pattern Help

▼

✅ Valid Examples

  • Simple digit capture:
    (?P<episode>\d+)
  • Season anchor (Recommended):
    \.S01E(?P<episode>\d+)\.
  • Flexible anchor:
    S\d{2}E(?P<episode>\d+)

❌ Invalid Examples

  • (\d+) - Missing named group
  • (.*) - Too greedy/vague
Note: Rename pattern must strictly use {<episode>} placeholder.
Grouping: added files are grouped automatically: names that share the words before their season/episode marker (or their first two words) and their extension get one rule, split by release when several files share the same ending. "Split all" gives every file its own rule, "Auto-group" regroups the whole board. Drag a file onto another rule to cover both with one regex: what differs between the names becomes .+, a number that only changes value becomes \d+, and the digit run chosen as the episode becomes (?P<episode>\d+). Click another digit run in the example line if the guess is wrong; − moves a file back to its own rule.

A folder that already holds files. Files already indexed and files an existing rule covers are listed apart; the others are grouped by the words their names share (the show name before a season/episode marker such as S01E03, 1x03 or Saison 1 Épisode 03, or the first two words, and the extension; a common ending such as the release tags splits two releases apart), one proposed rule per group; "Auto-group" and "Split all" redo the grouping. Save the rules you want, then index: VMSAM renames each matching file with its rule and registers it with the rule's weight. A file whose episode is already registered is left untouched.

Increment rules

The incrementaller renames a file in the watch folder before the folder rules run: the episode number it extracts is shifted by the increment and written into the rename pattern. Typical use: a release numbered from 1 for a season whose folder rules expect the absolute number.
